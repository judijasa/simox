# Keep nix & Composer pins in sync — Plan & Progress

## Decision

simox fetches two packages through two independent resolvers — nix
(`flake.nix` → `flake.lock`) and Composer (`composer.json` →
`composer.lock`):

- `judijasa/php-daas-framework` — explicit Composer `require` (dev-main,
  `type: vcs`) and a nix flake input.
- `judijasa/ema` — arrives transitively with php_daas_framework; simox keeps a
  `type: vcs` `repositories` entry for it but no `require` (Composer reads
  `repositories` only from the root package, so this entry is what lets
  Composer resolve ema at all).

Each lockfile pins an upstream commit independently, so the two can silently
drift. They already do: php_daas_framework flake `78c2d83…` vs Composer
`6883f00…`.

Add a pre-commit gate that detects when `flake.lock` or `composer.lock` is
staged and asserts both resolvers agree on the commit for every shared
package. On mismatch it blocks the commit and prints the fix.

Regenerating the counterpart lock on demand is only a convenience, not a
guarantee: a `dev-main` Composer constraint resolves to whatever `main` HEAD
is *now*, independent of the flake rev — so regenerating the other lock alone
can leave both freshly written but still pointing at different commits. The
rev-equality assertion is therefore the authoritative gate.

## Mechanism

Both lockfiles record the same 40-char commit SHA per package, so the check
is a direct string comparison. simox's own `flake.lock` already contains the
`ema` node (nix locks transitive inputs into the root lockfile), so the whole
comparison is local — no need to read another repo.

| package | `flake.lock` rev | `composer.lock` ref |
|---|---|---|
| php_daas_framework | `nodes.php_daas_framework.locked.rev` | `packages[]` `name == judijasa/php-daas-framework` → `source.reference` |
| ema | `nodes.ema.locked.rev` | `packages[]` `name == judijasa/ema` → `source.reference` |

The `ema` row is dormant until php_daas_framework starts `require`-ing ema (at
which point ema appears in `composer.lock` as a transitive package). Until
then the hook skips packages absent from `composer.lock`.

## Changes

### simox (simox)

- [ ] `hooks/pre-commit-lock-sync.sh` (new): when `flake.lock` or
      `composer.lock` is staged, extract each shared package's rev from both
      files with `jq`, assert equality, and fail with the fix instruction on
      mismatch. Skips packages absent from `composer.lock` (e.g. ema before
      php_daas_framework requires it).
- [ ] `.pre-commit-config.yaml`: register a `lock-sync` local pre-commit id
      pointing at the new script (mirrors the existing `composer` id).
- [ ] Resolve the existing php_daas_framework drift before the hook lands so
      the first run passes (see Open items for which direction to align).

### php_daas_framework (`../php_daas_framework`)

- [ ] Its own lock-sync hook for the ema pin, once it `require`s ema —
      tracked in `../php_daas_framework/doc/plans/2026-08-28-lock-sync.md`.

## Open items

- Which direction to align the current php_daas_framework drift: pin Composer
  to the flake rev (`dev-main#<rev>` then `composer update`), or move nix to
  Composer's commit (nix input override / `nix flake update`). Not decided.
- Recreate-vs-assert tradeoff: v1 asserts and blocks; auto-recreating the
  counterpart (the force-recreate trigger) is deferred until the rev-exact pin
  (`dev-main#<rev>`) is also adopted, so that recreate actually matches.
- The `ema` row stays a no-op until php_daas_framework requires ema via
  Composer (tracked separately); no cross-repo GUID wiring is implied.
